VictoriaLogs observability high-risk

Working narrative. Contract: overview/execplan/design/validation.md + decision 0012.

Why

The runner turn-dispatch timeout couldn't be diagnosed: server + runner log to terminals, browser console isn't captured. Goal: collect backend + frontend logs into one queryable store.

Architecture

browser console/errors ──POST /api/logs──▶ Bun server ──┐
                                                         ├──▶ VictoriaLogs 127.0.0.1:9428
backend console.* (server + local runner) ──jsonline────┘
  • VictoriaLogs in Docker, bound 127.0.0.1:9428 only (it holds chat content + tokens → never on the tailnet).
  • Backend: installConsoleTee() in cli.ts + runner.ts tees console to VL jsonline. Opt-in via VICTORIALOGS_URL; no-op otherwise.
  • Frontend: installClientLogShipper() in main.tsx → POST /api/logs → forwardClientLogs() → VL. Browser never touches VL (no CORS, VL stays private).

Design decisions

  • Fire-and-forget everywhere. Every shipping path swallows errors and never blocks. A down/slow VL must not back-pressure or crash the server, runner, or browser. This is the #1 rule for an observability shim.
  • Opt-in via VICTORIALOGS_URL. Unset ⇒ byte-identical to before. Lets us ship the code without forcing the dependency.
  • Server-side forward for the browser. Keeps VL localhost-only and avoids CORS. /api/logs always returns 204 — logging must never surface an error to the user.
  • Console monkeypatch (vs a custom logger everywhere). The codebase already uses console.* + LOG_PREFIX heavily; patching captures all of it with zero call-site changes, and is reversible (guarded, returns an uninstaller).
  • Input hardening on /api/logs: cap 1000 records, truncate msg 8KB, validate level/ts — a misbehaving client can't flood VL.

Deviations / open items

Live instance restart handed to the operator. The execplan's stop-condition fired: the live server process was already down when it came time to restart, so its exact launch flags couldn't be read from the running process. Per discipline I did not guess-launch the production instance; the precise restart command (with VICTORIALOGS_URL + NATS_ADVERTISED_HOST) is handed to the user.

Remote-runner logs not captured (V1). VL is localhost-only, so a runner on another machine can't reach it. Follow-up: ship remote-runner logs over the existing NATS connection to a server subject that forwards to VL. Logged to backlog.

No secret redaction yet. Logs may contain tokens/chat content. Mitigated by localhost-only + 7d retention; redaction is a follow-up before any wider exposure.

GitNexus impact not run (index read-only this session). Changes are additive (new modules + entrypoint installs + one endpoint); blast radius traced by reading the code.
