PR3 — Cross-machine Registration & Liveness + Versioning

Working narrative · Stage 2 implemented & verified

Contract: execplan/overview/design/validation.md; decision 0009. Stacks on PR2.

Design decisions

Heartbeat-TTL liveness, drop pid

Pure runnerLivenessState(lastHeartbeatAt, now) → online (<25s) / degraded (25–60s) / offline (≥60s), uniform for spawned + paired runners. The discover path stops using process.kill(pid,0) (meaningless across machines). pid kept informational only.

Versioning fails fast, never silently degrades

PROTOCOL_VERSION + SUPPORTED_RANGE; out-of-range runner → incompatible (distinct from offline) → turn start blocked with an upgrade message. No auto-update.

lastHeartbeatAt stays server-side

The server already owns the 10s heartbeat stream; tracking lastHeartbeatAt in memory avoids a KV write every 10s. Registration shape change (protocolVersion, capabilities?) is additive + ephemeral (re-registered) — no migration.

Stage 2 — implementation choices

lastSeenAt cadence: every heartbeat beat (10s)

Design allowed a coarser timer (e.g. every Nth beat). We write on every beat for simplicity in the pilot. A missed write ages the cached value naturally — bounded by heartbeatIntervalMs. The KV put is fire-and-forget; a failure just lets the previous timestamp coast.

RUNNER_HEARTBEAT_TIMEOUT_MS removed

The 30s constant was the old freshness threshold, now superseded by runnerLivenessState (25s/60s thresholds). Removing it avoids a dead-constant TS error and keeps the single source of truth in runner-protocol.ts.

ensureRunner liveness check (spawn mode)

The existing re-entry path used process.kill(reg.pid,0). Replaced with runnerLivenessState(lastHeartbeatAt ?? reg.lastSeenAt, now) — prefers the live server-tracked heartbeat, falls back to KV lastSeenAt if the subscription hasn't received a beat yet.

Deviations

None from design.md. The discover-path incompatible-runner skip was described as "adopt-and-mark OR skip"; we chose skip (fail fast, consistent with the turn-start gate philosophy).
