Working narrative

This file tracks how the implementation gets to the contract in story.md. Updated as work proceeds — not just at the end. Status: implemented + verified end-to-end (write_file, edit_file, missing-file, desktop + mobile). Remaining nicety: a touch toggle for the sidebar (Cmd+B only today).

Design decisions (from the /grill-me dialog)

Entry points: both. Per-card "Open" button on write_file/edit_file cards and a consolidated "Touched files (N)" list. The two serve different moments — immediacy vs. review-before-proceeding.
Content source: fresh from disk. Reuse system.readLocalFilePreview. Matches the use case (review the actual file), and means edit_file "Open" reads the whole current file, not the old/new diff.
Index: client-side derivation. Scan in-memory render units for write/edit tool calls; dedup by path (latest wins); no server read-model, no event-sourcing. The panel only needs paths + a created/edited label since content is read on open.
Surface: reuse ContentOverlay modal. Already used by LocalFilePreviewDialog — free TOC/copy/zoom/mobile slide-up.
Panel home: fill the existing RightSidebar placeholder. It currently shows "diffs coming soon" and already owns all the responsive plumbing (toggle animation, resizable %, isMobileViewport, edge-swipe). Best fit for mobile + web without building a new surface. A composer chip was rejected: it would rebuild responsive behavior and compete for the tightest mobile real estate.
Type map: extension → renderer, code fallback. .md→markdown, .html→HTML, .svg→SVG, .mmd→Mermaid, .d2→D2, .pug→Pug; else syntax-highlighted code. iframe/diashort excluded — they are remote URLs, not files.
Security: reuse command as-is, no new scoping. No new read capability — the command already reads any file and is already client-callable via link previews. We only ever pass paths the agent itself wrote/edited.

Why HTML is safe by reuse

EmbedRenderer's HtmlEmbed renders into an <iframe sandbox="allow-scripts"> with no allow-same-origin, so agent-authored HTML cannot reach the app origin. Mermaid runs with securityLevel: "strict"; SVG renders as an inert data-URL <img>; Pug compiles to HTML and goes through the same sandbox. Caveat (pre-existing): the HTML sandbox loads the Tailwind browser CDN from jsdelivr — a network call.

Tradeoffs considered

Disk vs snapshot. Snapshot avoids a round-trip and survives deletion, but is stale after later edits and edit_file only carries old/new strings. Chose disk = truth, with explicit missing/too-large/binary states.
Client derivation vs server read-model. Server projection survives transcript truncation, but it's a real schema+responder+event-handler build for data we can already derive. Chose client; flagged the truncation risk below.

Open questions / risks

Transcript pagination. If render units are paginated/truncated, very old touched files may not be in memory and would drop off the client-derived list. Mitigation if it bites: record via scripts/harness backlog add and consider a server read-model then — do not add silently.
Modal iframe height. EmbedRenderer uses a fixed 420px iframe height suited to inline embeds; a full-file preview in the modal should fill available height. Recommendation: pass through / override height in the overlay context. To confirm during build.

Mobile bug + fix (2026-05-26)

Bug (user-reported): no preview button on mobile. Root cause: the per-card button lived inside ExpandableRow.expandedContent, which renders only when the card is individually expanded, and the expand chevron is opacity-0 until hover. Mobile has no hover → cards look non-expandable → button unreachable. (It was hover-gated on desktop too, just discoverable via hover.)
Fix: added an optional headerAction slot to ExpandableRow (rendered in a flex row beside the toggle button, outside it) and moved the "Open preview" button there for write/edit cards. Now always visible on the card header, independent of expansion, on both desktop and mobile. TDD: ToolCallMessage.test.ts asserts write/edit cards expose "Open preview" in static markup and bash does not.

Re-verified in running app: @390px the button is on-screen and a tap opens the modal (markdown rendered). edit_file card shows the button and opens the edited content (fresh from disk). Deleted file → graceful "Path not found" toast, no modal/crash.

Open follow-up: the RightSidebar "Touched files" panel still opens only via Cmd+B — unreachable by touch on mobile. The per-card button covers the mobile entry point; a visible sidebar toggle is a recommended follow-up (TEST_MATRIX row "RightSidebar panel reachable on mobile" = planned).
