US-RPAH — Pairing exchange advertises a routable NATS host normal lane

Working narrative for the fix. The contract lives in story.md beside this file.

Symptom → root cause

A runner paired from a second machine crashed at startup with ConnectionError: connect ECONNREFUSED 0.0.0.0:50640.

The pairing exchange returned the embedded NATS daemon URL verbatim. When the server is started with --remote / --host 0.0.0.0, that URL is nats://0.0.0.0:<port>. 0.0.0.0 is a bind-all wildcard, never a valid client destination. A remote runner dials it, the OS routes it to the runner's own loopback, nothing listens there, and the connection is refused. Same-machine pairing accidentally "works" because 0.0.0.0 loops back to where the daemon actually is.

Trace: cli-runtime.ts:130 (bind 0.0.0.0) → server.ts hostname → NATS_HOST (nats-daemon-manager.ts:85) → nats-daemon-callout.ts:119 builds nats://${host}:${port} → daemonInfo.url → pairing exchange returns it (server.ts:986).

Design decisions

  • Reuse the existing advertised-host concept. /auth/token already honors NATS_ADVERTISED_HOST (server.ts:931) and NatsBridge already has a 0.0.0.0 → 127.0.0.1 normalize. The pairing exchange was the one path that ignored both. The fix brings it in line rather than inventing a new mechanism.
  • Refuse, don't guess. When bound to a wildcard host and no NATS_ADVERTISED_HOST is set, we cannot know the routable address. Returning 127.0.0.1 would be wrong for a remote runner (it means "this runner's machine"). So the exchange returns HTTP 409 with an actionable message instead of shipping a broken credential. Loud failure at pairing time beats a silent ECONNREFUSED at runner startup.
  • New self-contained module src/server/runner-pairing-urls.ts with a pure resolveRunnerPairingUrls() returning a discriminated { ok } | { ok:false, error }. Pure → unit-testable in ~10ms with no server boot.

Tradeoffs

ChoiceAlternativeWhy
Local rewriteUrlHost in the new module Import/export it from nats-bridge.ts nats-bridge.ts pulls in the native @lagz0ne/nats-embedded dep. Keeping the helper standalone makes its unit test fast and dependency-free. ~6 lines duplicated, acceptable.
409 on wildcard + no advertised host Fall back to 127.0.0.1 127.0.0.1 is correct only for same-machine pairing and silently wrong for the remote case this story exists to fix.

Deviations

None from the agreed approach. Scope held to the host bug.

Open questions

Ephemeral NATS port (out of scope, logged to backlog). The embedded daemon binds an ephemeral port (NATS_PORT default -1, nats-daemon-callout.ts:26). The paired credential is long-lived (90 days) but the port inside it only survives until the next server restart, after which every paired runner's stored URL is stale. Recommendation: default the embedded NATS port to a stable value (or persist + reuse it) so durable pairing is actually durable. Tracked in docs/HARNESS_BACKLOG.md.
