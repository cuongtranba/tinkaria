Design decisions

Reorder = Move up/down, not drag-and-drop. Deterministic, testable, accessible, identical on both surfaces. Drag deferred (decision 0006).
New fields are optional (pinned?, sortOrder?) so existing persisted snapshots/events stay valid — no migration.
Reorder writes the full ordered id list (one event rewrites every sortOrder) to avoid sparse-index drift.

Bugs found during running-app verification

1. SERVER_COMMANDS allowlist. The Bun server subscribes to one NATS subject per command type listed in SERVER_COMMANDS (nats-responders.ts). The new rename/set-pinned/reorder commands weren't listed, so they had no subscriber and the client request silently no-op'd (event log stayed empty, UI didn't change). Fix: added the three types to the list. This is exactly why the dual-signal rule matters — the UI looked broken with no client error.
2. read-model ordering. The client-facing list came from read-models.ts, which sorted by updatedAt desc — ignoring pinned/sortOrder entirely (and since rename/pin/reorder bump updatedAt, unpin would have mis-sorted). Fix: extracted a shared compareIndependentWorkspaces in shared/types.ts used by both the read-model and listIndependentWorkspaces so the snapshot and live view agree.
